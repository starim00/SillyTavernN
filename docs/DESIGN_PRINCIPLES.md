# 产品与设计准则

SillyTavern N 是兼容既有内容生态的 AI 角色扮演工作区，由浏览器前端、服务端和持久化存储共同组成。设计以角色卡、连续对话和可恢复的数据为中心。

## 角色卡与对话

- 角色卡是统一内容包，包含设定、开场、提示词字段和嵌入世界书。Persona 是用户身份配置，应与卡内人物设定区分。
- 用户先选择角色卡，再打开该卡的聊天记录或新建对话；每个对话归属一张卡。
- 卡可以描述多人、旁白或整个世界。界面不展示 character、ensemble、scenario、world 等卡种分类，也不把一段模型回复拆成多人轮流发言。
- 内部兼容字段和参与者资料不改变上述产品模型。不要从 `kind`、`participants` 或兼容合同中的数组字段推导新的导航方式。
- 用户消息显示 Persona 名称，模型消息显示角色卡名称。Provider 来源按 Swipe 保存和展示；历史来源未知时留空，不使用当前连接补猜。

## 工作区与视觉

- 预设调整是高频操作：桌面左侧直接展示预设、生成参数与提示词条目，允许边聊边调；窄屏通过明确的预设入口打开抽屉。
- 聊天历史切换是次要操作，保留集中菜单入口即可，不常驻占据侧栏。人设切换属于低频管理，放在工作区设置中，不占顶栏主操作区或输入区。
- 顶栏突出当前对话并保留预设、角色卡与设置入口。角色卡列表中，标题和描述使用完整行宽，新建对话与更多维护操作置于独立操作行。
- 使用通用、克制且轻快的工作区布局。角色图片是用户导入的内容，不是页面结构或装饰背景。
- 使用暖白底色、浅蓝选中态、薄荷绿状态、珊瑚色主要操作、冷灰边框和深蓝灰文字；复用 `apps/web/src/styles.css` 中的实际 token。
- 应用控件使用 Phosphor 图标，不引入 emoji、手绘 SVG、CSS 插画或占位装饰图。此约束不限制用户导入内容。
- 消息流保持主要阅读空间；上下文、世界书命中、提示词追踪和模型工具活动作为可折叠辅助区域。
- 消息按内容自然展开，对话区域只保留一个消息滚动容器。输入框从紧凑单行随草稿增长，并有高度上限。
- 窄屏应允许面板收起、表单换行并处理安全区域；长键名、深层变量和嵌入文档不能撑宽工作区或遮挡操作。
- 变量管理同时保留原始 JSON 批量编辑和可折叠树形编辑，支持节点编辑、保存与取消。提示词 Token 信息同时提供总览和条目明细。

## 状态与生成

- SQLite 和服务端配置是共享数据的依据。预设与 Provider 选择保存在服务端；当前卡、对话位置和未发送草稿可以保存在浏览器。
- 服务端接收生成请求后持有任务。SSE 断开不等于取消；刷新后恢复任务状态、读取已保存结果，并完成浏览器侧兼容处理。
- 重生成必须从正确的历史和变量快照构造提示词，不能把被替换的最新回复作为新的输入历史。
- 消息删除从选中楼层起删除该楼层及后续内容，确认界面应清楚显示范围。相关变量和衍生数据需要保持一致。
- 完成提示音仅在回复完整完成且页面未聚焦时触发。

## 兼容与信任

- 这是独立的新实现。上游只用于观察格式和行为，不复制源代码；测试素材应最小化、自行编写且不含私人对话或凭据。
- 保留可兼容的未知字段、禁用预设项和脚本数据；保留数据不等于启用执行，也不意味着所有上游功能均已实现。
- 导入的可执行来源默认不受信任。用户信任整张卡、预设或脚本来源后，按旧 SillyTavern 浏览器模型执行：主页面后台脚本、无 sandbox 的同源消息 iframe、直接 DOM、浏览器存储、Tavern Helper/MVU 和普通网络访问。
- 不对已信任的旧脚本增加逐能力授权、网络代理、DOM/storage 代理或源代码改写。iframe 不是安全边界。
- 原生扩展 SDK 的 Worker、manifest 和 capability 合同是另一条运行路径，不能套用到上述卡片脚本上。
- Provider 密钥和直接数据库句柄留在服务端。固定版本插件安装校验与导入脚本来源信任是两件独立的事。

## 对话内模型工具

- 工具随普通聊天请求提供。Agent run 是内部执行状态，不引入独立 Agent 聊天、目标输入或规划页面。
- 模型只能调用服务端注册的工具；工具写入与旧脚本使用不同 actor，权限不能互相推导。
- 世界书授权在条目级。导入条目的 `agentEditable` 强制为 `false`；整本世界书的旧标记仅是兼容元数据。
- 创建条目需要用户确认，新条目默认不可由模型修改；更新和删除还要求目标条目已明确允许模型修改。模型不能更改该权限。
- 当前非只读工具均要求确认。确认不能替代权限、revision、作用域或取消状态检查；这些检查应在实际写事务内执行。
- 成功写入与审计、逆向补丁一起提交。撤销由用户发起并检查冲突，不覆盖后续修改。摘要和参与者档案是衍生资料，不直接重写角色卡定义。
